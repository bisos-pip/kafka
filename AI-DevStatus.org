* Architecture
  - =py3/bisos/kafka/kafkaInfo.py= --- the single source of facts. Everything else
    imports it: pinned versions + checksums (Kafka SHA-512 from Apache, Kafbat SHA-256
    from the GitHub asset digest, librdkafka SHA-256 of the tag's archive), paths, banna ports,
    generators of /etc/kafka/server.properties, /etc/default/kafka, /etc/default/kafbat-ui, the units'
    identity lines and librdkafka's build-env.sh, and kvDrift()/unitDrift() for driftCheck.
  - Layout on a host:
    | /opt/kafka/kafka_2.13-4.3.1, /opt/kafka/current -> it | root, read-only     |
    | /opt/kafka/kafbat/api-v1.5.0.jar                      | root               |
    | /opt/kafka/librdkafka-2.16.0, /opt/kafka/librdkafka -> it, build-env.sh | root |
    | /etc/kafka/server.properties, /etc/default/kafka{,bat-ui} | root:kafka 640 |
    | /var/lib/kafka/data (KRaft meta + partitions), /var/log/kafka | kafka 750/755 |
  - =py3/bin/=:
    - kafka-cbs.pcs (CBS: kafkaCbs-sbom.pcs + units [kafka, kafbat-ui] + kafka-assemble.cs)
    - cbmProc-kafka.spcs (CBM pointer; leaf sys/cbm/collective/hereWeb/kafka/)
    - Three sboms (WorkPlan 2.7, 2026-10-15). kafka-sbom.pcs, the server only: apt openjdk-25-jre-headless + curl,

* Key Design Decisions
  - *Public-only repo* (user, 2026-10-14): nothing about any particular consumer. bisos.kafka is a mechanism;
    every consumer-specific value (topic, key, headers, identity headers, output path, security settings) is a
    parameter; a consumer's repository supplies them. Test data and docs use neutral names.
  - hereWeb (like airflow), not bedrock (like postgres): kafka has a web UI at kafka.here.
  - *Service and usage sboms* (user, 2026-10-15; WorkPlan 2.7): kafka-sbom.pcs (server) does NOT pull in
    kafkaUsage-sbom.pcs; the CBS does both, through kafkaCbs-sbom.pcs, because cba_seed.setup(sbom=...) takes one
    string. "Usage", not "Client". Out of chain: the general rule is in the cbm-authorship skill
    (/bisos/git/bxRepos/bisos/defaults/ai-templates/bisos-pip/_skills/, under git); the framework limit and a
    second finding (sbomSpecs_fullUpdate carries on after a failed sub-sbom) are in AI-Outputs.org (blee-binders,
    under git). Actionable when cba_seed accepts a list: retire kafkaCbs-sbom.pcs.
  - Upstream binaries, pinned + checksummed, in kafkaInfo: Debian packages neither Kafka
    nor Kafbat UI. Bumping a version means bumping its checksum; a mismatch aborts the sbom.
    Fetched from archive.apache.org (downloads.apache.org keeps only recent releases).
  - Java 25: Kafbat UI 1.5.0 is compiled for it (class file 69); 21 crash-looped. One JRE serves both.
  - Kafbat UI as a plain jar under systemd, no Docker.
  - Loopback-only listeners: Kafbat UI has no authentication. Hence kafka-wvd.pcs proxies to
    kafkaInfo.listenIp (127.0.0.1), NOT socket.gethostbyname(fqdn) as airflow-wvd.pcs does.
  - Single node: every internal-topic replication factor is 1 (stock 3 would leave __consumer_offsets
    uncreatable and break the first transactional send). controller.quorum.bootstrap.servers, format --standalone.
  - Config files written only when absent (hand overrides survive); kafkaAdmin.cs -i driftCheck
    reports drift instead of overwriting --- same pattern as airflow's /etc/default/airflow.
  - Storage formatted only when meta.properties is absent; checked with =sudo test= because
    dataDir is kafka-owned 750 (a plain [ -f ] by the invoker always sees it missing).
  - kafbat-ui Wants= (not Requires=) kafka.service: the UI stays up while the broker restarts.
  - No ExecStop= on kafka.service: systemd SIGTERM is Kafka's graceful shutdown;
    kafka-server-stop.sh signals every Kafka on the host. SuccessExitStatus=143.
  - nginx vhost written in kafka-wvd.pcs (not webVd_nginxSites.atPortSite) to add
    proxy_buffering off + proxy_http_version 1.1.
  - banna (out-of-chain record: commit 115db49 in bisos-pip/banna, under git):
    /etc/hosts IPs are now stored per port (TcpPortNuInfo.hereIp/hereName) instead of
    derived from sorted position --- the old scheme would have shifted six existing
    .here names by 3 when the kafka ports were added. Existing names keep their IPs;
    kafbatUi carries hereName="kafka"; the broker/controller ports have no .here name;
    _dev ports keep theirs (Mohsen's decision). Import-time check rejects duplicate IP/name.
    tcpPorts.hereIpOf() lets wvd files avoid depending on /etc/hosts being current.
  - The kafka account's uid/gid = 503 come from bisos.banna.sysAccts (banna Stage 3,
    record in banna's AI-WorkPlan.org), not from useradd's auto-selection, so they are
    the same on every platform. kafka-sbom.pcs uses sysAccts.useraddScript(): it creates
    the account with 503 when absent, only warns if an existing kafka account has other
    numbers, and refuses if 503 is held by someone else. bisos.banna's registry range is
    500-999 without touching /etc/login.defs (Mohsen's decision).
  - *Client library*: confluent-kafka, chosen on measurement (transactions pass; ~430k vs ~18k records/s for
    kafka-python 3.x; kafka-python 2.0.x does not import on Python 3.12+), behind _client() and two functions
    (sendFiles, receiveFiles): swappable. Its Linux wheels lack Kerberos, so kafka-sbom.pcs builds a pinned,
    checksummed librdkafka with GSSAPI and writes build-env.sh. build-env.sh sets PIP_NO_BINARY and
    PIP_NO_CACHE_DIR: pip silently reuses a cached wheel built against another library. A dotless broker host
    name can be expanded by the host's DNS search domains into the wrong Kerberos realm (KRB5_TRACE shows it).
  - *File transfer* (WorkPlan Stage 2, "The concept"): commands named Send and Receive ("source"/"sink" are Kafka
    Connect words and clash with a record's own source attribute); two thin real .cs over one csu, no $0 dispatch.
    Records mode is the base (value = the line without terminator, headers from parameters, one transaction per
    file). The optional file model puts kfx-bof (declared: path, attrs, bytes, rows, sha256, eol, finalEol,
    idHeaders, hdr) on the first record and kfx-eof (observed) on the last; a rows-only consumer ignores them. The
    receiver demultiplexes interleaved files by the headers the BOF names, verifies, and places atomically.
    Known limits by decision: lines only, benevolent senders, non-empty files, files held in memory.
  - The PyCS main discards a Cmnd's outcome (a failed Cmnd would exit 0): the file-transfer Cmnds raise
    SystemExit(1) after reporting a failure. No framework change (the framework is not edited from here).
  - A rejected file (bad marker, hostile path) must not stop the stream: FileAssembler.feed raises only
    VerifyError and the receiver carries on (found by the integration test; a poison-pill defect).
