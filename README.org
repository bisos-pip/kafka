* Overview

/bisos.kafka/ is a BISOS package for running Apache Kafka on a BISOS host ---
a single-node broker in KRaft mode (no ZooKeeper), together with
[[https://github.com/kafbat/kafka-ui][Kafbat UI]] as its web UI --- as a BISOS
Capability Bundle (CBS/CBM) of =systemd=-planted Command Services.

A planted pointer leaf (=cbmProc.spcs=, at
=sys/cbm/collective/hereWeb/kafka/=) subprocess-invokes a Capability Bundle
Specification (=kafka-cbs.pcs=). The CBS declares package installation (sbom),
the two =systemd= units (=kafka= and =kafbat-ui=), and the assembly step that
makes Kafbat UI browsable as =http://kafka.here=.

Debian packages neither Kafka nor Kafbat UI. The sbom therefore takes only the
JRE from apt, and fetches the Apache Kafka binary tarball and the Kafbat UI jar
from upstream at pinned versions, refusing either one if its checksum does not
match.

* What Gets Installed, and Where

Every fact below lives in one place, =py3/bisos/kafka/kafkaInfo.py=, which the
sbom, the units, the dns and vhost files and the admin CS all read.

| What                        | Where                                     | Owner          |
|-----------------------------+-------------------------------------------+----------------|
| JRE (=openjdk-21-jre-headless=) | apt                                   | root           |
| The =kafka= account and group | uid/gid 503, from bisos.banna =sysAccts= | ---         |
| Kafka 4.3.1 (Scala 2.13)    | =/opt/kafka/kafka_2.13-4.3.1=             | root           |
| Active Kafka version        | =/opt/kafka/current= -> the above         | root           |
| Kafbat UI 1.5.0             | =/opt/kafka/kafbat/api-v1.5.0.jar=        | root           |
| Broker config               | =/etc/kafka/server.properties=            | root:kafka 640 |
| Broker environment          | =/etc/default/kafka=                      | root:kafka 640 |
| Kafbat UI environment       | =/etc/default/kafbat-ui=                  | root:kafka 640 |
| KRaft metadata + partitions | =/var/lib/kafka/data=                     | kafka          |
| Application logs            | =/var/log/kafka=                          | kafka          |

The account's numbers come from banna's registry, not from =useradd='s per-host choice,
so =kafka= is 503 on every platform; the sbom refuses if 503 is already taken.

The three config files are written only when absent, so hand overrides survive
re-runs of the sbom. =kafkaAdmin.cs -i driftCheck= reports how a live file
differs from what its generator would write.

Storage is formatted (=kafka-storage.sh format --standalone=) only when
=/var/lib/kafka/data/meta.properties= is absent. Formatting a used data
directory again would mint a new cluster id and orphan every topic.

* The 2 systemd Units

| Unit                 | Runs                                         | Ordering                                  |
|----------------------+----------------------------------------------+-------------------------------------------|
| =kafka-sysd.pcs=     | =kafka-server-start.sh /etc/kafka/server.properties= --- broker and KRaft controller in one process | =After=network.target=                    |
| =kafbat-ui-sysd.pcs= | =java -jar api-v1.5.0.jar=, configured by =/etc/default/kafbat-ui= | =After=/=Wants=kafka.service=              |

Both run as =User=kafka=. Kafbat UI uses =Wants== rather than =Requires==, so
it stays up, showing the cluster as offline, while =kafka.service= restarts.

* Listeners and Ports

Ports are assigned in =bisos.banna= (=tcpPorts.py=), never hardcoded. Every
listener binds loopback only: the broker serves this host's tenants, and
Kafbat UI has no authentication.

| Listener               | Address           | banna name        |
|------------------------+-------------------+-------------------|
| Broker (PLAINTEXT)     | =127.0.0.1:24007= | =kafka=           |
| KRaft controller       | =127.0.0.1:24008= | =kafkaController= |
| Kafbat UI              | =127.0.0.1:24009= | =kafbatUi=        |
| Kafbat UI, via nginx   | =http://kafka.here= | ---             |

Clients use =bootstrap.servers=127.0.0.1:24007=.

* Installation

The sources for the bisos.kafka pip package are maintained at:\\
https://github.com/bisos-pip/kafka

The bisos.kafka pip package is available at PYPI as\\
https://pypi.org/project/bisos.kafka

You can install bisos.kafka with pip or pipx.

** Installation With pip

If you need access to bisos.kafka as a python module, install it with pip:

#+begin_src bash
pip install bisos.kafka
#+end_src

** Installation With pipx

If you only need access to bisos.kafka on the command line, install it with pipx:

#+begin_src bash
pipx install bisos.kafka
#+end_src

The following commands are made available:

- =kafkaAdmin.cs= --- day-to-day admin CS for this host's =kafka.here= installation.
- =quickKafka.cs= --- direct-command cheat sheet for the Kafka CLI tools and the two =systemd= units.
- =kafka-assemble.cs= --- assembly step: =kafka.here= dns entry and nginx vhost.
- =cbmProc-kafka.spcs= --- planted CBM pointer that materializes the CBS at this host.

The planted =.pcs= files (=kafka-cbs.pcs=, =kafka-sbom.pcs=, =kafka-sysd.pcs=,
=kafbat-ui-sysd.pcs=, =kafka-here-dns.pcs=, =kafka-wvd.pcs=) are invoked
directly from =py3/bin/=.

* Usage

** Materialization

#+begin_src bash
kafka-sbom.pcs -i sbom_fullUpdate                    # install only
kafka-cbs.pcs -i cbs_materialize                     # sbom + units + assemble
cbmProc-kafka.spcs -i cbm_enable                     # at the planted CBM leaf, then:
cbmProc-kafka.spcs -i cbm_materialize
#+end_src

** Day-to-Day Admin: =kafkaAdmin.cs=

Run with no arguments (or =-i examples=) to see the full menu. Key
sub-commands:

#+begin_src bash
kafkaAdmin.cs -i hostInfo             # fqdn, listeners, install/config/data/log paths
kafkaAdmin.cs -i servicesInfo         # links for operating the 2 systemd units
kafkaAdmin.cs -i topicsInfo           # create, list, describe, produce, consume
kafkaAdmin.cs -i consumerGroupsInfo   # list, lag, reset offsets
kafkaAdmin.cs -i driftCheck           # read-only: live config and units vs kafkaInfo
kafkaAdmin.cs -i fullUpdate           # the four info Cmnds together
#+end_src

** Direct Kafka CLI Cheat Sheet: =quickKafka.cs=

For direct =kafka-*.sh= / =systemctl= / =journalctl= invocations, and hints for
reading Kafbat UI, run:

#+begin_src bash
quickKafka.cs
#+end_src

* Key Files

- =py3/bisos/kafka/kafkaInfo.py= --- the single source of facts: pinned versions and checksums, paths, ports, and the generators of the three config files and the units' identity lines.
- =py3/bin/kafka-cbs.pcs= --- CBS declaring the bundle (sbom + 2 sysd units + assemble).
- =py3/bin/cbmProc-kafka.spcs= --- planted CBM pointer leaf that materializes the CBS.
- =py3/bin/kafka-sbom.pcs= --- package installation via [[https://github.com/bisos-pip/sbom][bisos.sbom]]: the JRE from apt, then Kafka and Kafbat UI from upstream.
- =py3/bin/kafka-sysd.pcs=, =py3/bin/kafbat-ui-sysd.pcs= --- the two units.
- =py3/bin/kafka-assemble.cs= --- assembly step (dns + vhost).
- =py3/bin/kafka-here-dns.pcs= --- =.here= fake-domain DNS registration for =kafka.here=.
- =py3/bin/kafka-wvd.pcs= --- nginx vhost for =kafka.here=, proxying (unbuffered, for Kafbat UI's message streaming) to Kafbat UI on loopback.
- =py3/bin/kafkaAdmin.cs=, =py3/bin/quickKafka.cs= --- admin CS and cheat sheet.
- =py3/tests/verify.sh= --- smoke test for =kafkaAdmin.cs= and =quickKafka.cs=.
- =py3/setup.py=, =py3/pypiProc.sh= --- PyPI packaging (setup.py is dblock-driven; do not hand-edit).
