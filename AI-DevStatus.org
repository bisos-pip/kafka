* Key Design Decisions
  - *Public-only repo* (user, 2026-10-14): nothing about any particular consumer. bisos.kafka is a mechanism;
    every consumer-specific value (topic, key, headers, identity headers, output path, security settings) is a
    parameter that the consumer's repository supplies. Test data and docs use neutral names.
  - hereWeb (like airflow), not bedrock (like postgres): kafka has a web UI at kafka.here.
  - *Service and usage sboms* (user, 2026-10-15; 2.7): kafka-sbom.pcs does NOT pull in kafkaUsage-sbom.pcs
    (materializing only the server is normal); the CBS does both, through kafkaCbs-sbom.pcs, because
    cba_seed.setup(sbom=...) takes one string. "Usage", not "Client" (dbClients in bisos.postgres is fine: its
    scope is SQL generally). No sbom installs confluent-kafka. Finding: airflow was never split, despite the
    TODO's wording; postgres's dbClients-sbom.pcs was the nearest precedent.
  - Out of chain (all under git): the general CBM-package pattern is the cbm-package-authorship skill and the
    sbom split is in cbm-authorship (/bisos/git/bxRepos/bisos/defaults/ai-templates/mother/_skills/).
    AI-Outputs.org (blee-binders/evolution) holds: cba_seed takes one sbom (WORKAROUND; retire
    kafkaCbs-sbom.pcs when it takes a list); sbomSpecs_fullUpdate carries on after a failed sub-sbom (TODO);
    the CBM-package helpers copied into every package (TODO; kvDrift/unitDrift here are among them).
  - Upstream binaries, pinned + checksummed in kafkaInfo: Debian packages neither Kafka nor Kafbat UI. Bumping
    a version means bumping its checksum; a mismatch aborts the sbom. Fetched from archive.apache.org
    (downloads.apache.org keeps only recent releases).
  - Java 25: Kafbat UI 1.5.0 is compiled for it (class file 69); with 21 it crash-looped
    (UnsupportedClassVersionError). One JRE serves both.
  - Kafbat UI as a plain jar under systemd, no Docker.
  - Loopback-only listeners: Kafbat UI has no authentication. kafka-wvd.pcs proxies to kafkaInfo.listenIp
    (127.0.0.1), NOT socket.gethostbyname(fqdn) as airflow-wvd.pcs does; it writes its own vhost (not
    webVd_nginxSites.atPortSite) to add proxy_buffering off + proxy_http_version 1.1 for Kafbat's streaming.
  - Single node: every internal-topic replication factor is 1 (stock 3 leaves __consumer_offsets uncreatable
    and breaks the first transactional send). controller.quorum.bootstrap.servers, format --standalone.
  - Config files written only when absent (hand overrides survive); driftCheck reports instead of overwriting.
  - Storage formatted only when meta.properties is absent; checked with =sudo test= because dataDir is
    kafka-owned 750 (a plain [ -f ] by the invoker always sees it missing). Formatting again would mint a new
    cluster id and orphan every topic.
  - kafbat-ui Wants= (not Requires=) kafka.service: the UI stays up while the broker restarts.
  - No ExecStop= on kafka.service: systemd's SIGTERM is Kafka's graceful shutdown; kafka-server-stop.sh signals
    every Kafka on the host. SuccessExitStatus=143.
  - banna (commit 115db49 in bisos-pip/banna): .here IPs are stored per port (hereIp/hereName), not derived from
    sorted position, which would have shifted six existing names by 3 when the kafka ports were added.
    kafbatUi carries hereName="kafka"; broker and controller have no .here name; _dev ports keep theirs
    (Mohsen's decision). tcpPorts.hereIpOf() lets wvd files avoid depending on /etc/hosts being current.
  - The kafka account's uid/gid 503 come from bisos.banna.sysAccts (banna Stage 3), through
    sysAccts.useraddScript(): created with 503 when absent, a warning if an existing account differs, a refusal
    if 503 is taken. The registry range is 500-999 without touching /etc/login.defs (Mohsen's decision).
  - *Client library*: confluent-kafka, chosen on measurement (transactions pass; ~430k vs ~18k records/s for
    kafka-python 3.x; kafka-python 2.0.x does not import on Python 3.12+), behind _client() and two functions
    (sendFiles, receiveFiles): swappable. build-env.sh sets PIP_NO_BINARY and PIP_NO_CACHE_DIR: pip silently
    reuses a cached wheel built against another library. A dotless broker host name can be expanded by the
    host's DNS search domains into the wrong Kerberos realm (KRB5_TRACE shows it). Record:
    KafkaUsePython.org (in this repo, verified 2026-10-14 against this host's broker and a private KDC).
  - *File transfer* (Stage 2, "The concept"): Send and Receive ("source"/"sink" are Kafka Connect words and clash
    with a record's own source attribute); two thin real .cs over one csu, no $0 dispatch. Records mode is the
    base (value = the line without terminator, headers from parameters, one transaction per file). The optional
    file model puts kfx-bof (declared) on the first record and kfx-eof (observed) on the last; rows-only
    consumers ignore them. The receiver demultiplexes interleaved files by the headers the BOF names, verifies,
    and places atomically. Known limits by decision: lines only, benevolent senders, non-empty files, files held
    in memory. The "Try it" pair uses topic and group kafkaFileDemo and /tmp/kafkaFileDemo (a subdirectory, not
    /tmp itself).
  - The PyCS main discards a Cmnd's outcome (a failed Cmnd would exit 0): the file-transfer Cmnds raise
    SystemExit(1) after reporting a failure. No framework change.
  - A rejected file (bad marker, hostile path) must not stop the stream: FileAssembler.feed raises only
    VerifyError and the receiver carries on (a poison-pill defect found by the integration test).
